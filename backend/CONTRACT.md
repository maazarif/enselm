# Relay contract v1
POST /api/relay only. JSON wrapper {invitation, audience (exact request origin), timestamp (integer unix ms), nonce (UUID), action, payload, signature}. Signature: ECDSA P-256 SHA-256 over UTF-8 JSON.stringify({v:1,domain:'enselm-relay-v1',audience,timestamp,nonce,action,payload}), exact property order. invitation is existing PFCore.invitation, verified fingerprint; signature key from invitation. 5 minute timestamp window, nonce consumed per identity for 10 minutes. Response JSON; errors {error: string}. All responses no-store. No CORS; reject foreign Origin, allow absent Origin for signed clients. Max request 6MB, bounded streamed read.
Actions:
- enable {}: enroll identity mailbox; response {enabled:true}. Private keys never sent. Enabled mailbox required for all actions except enable/status. Limits 1000 enrolled identities per deployment.
- status {}: {enabled:boolean}. No account creation.
- allow {sender:64hex}: recipient explicitly allows sender. response {allowed:true}. Grant limit 100 per mailbox.
- revoke {sender}: remove allowance AND queued messages from sender; {allowed:false}.
- send {envelope}: existing signed encrypted PFCore envelope. identity must equal envelope.from.id; recipient mailbox enabled and grant exists. Max queue 30 messages and 8 MiB/recipient, max 512 KiB encoded envelope per request (larger photos use encrypted file exchange). TTL 7 days; idempotent same envelope id per sender; differing body under same ID reject. Return {queued:true,id,expiresAt}; never claim read/delivery. Quota and allow checks atomic SQL conditional insert. Sender max 100 sends/day; per identity API max 120/minute. Existing tombstones retain ID until expiration.
- inbox {}: {messages:[envelope...]} up to 30; no auto acknowledgment or decryption. Expired payloads excluded/cleaned on requests (no hard real-time deletion guarantee). Reading only on user action.
- ack {ids:[max30 UUID/string<=80]}: remove ciphertext for owned mailbox records; keep ID/hash tombstones until expiration. {removed:true}. Client only acknowledges after encrypted local persistence succeeds; session-only imports stay queued.
- disable {}: revoke mailbox, grants and queued incoming messages; {enabled:false}. Does not erase other recipients' queues.
No directory/search, presence, push, polling, read receipts, plaintext, passwords or private keys. Keys authenticated each request; no cookies/tokens. Existing custom file crypto unchanged, no forward secrecy claim. Host metadata exists. Owner-private hosting preserved, so separate people cannot yet access this deployment without explicit audience expansion.
